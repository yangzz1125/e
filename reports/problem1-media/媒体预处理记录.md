# 问题一：全片媒体预处理记录（已完成，非三模态特征结果）

输入：服务器`/hy-tmp/mathmodel/E/input/`中的附件1，原始文件只读。正式脚本：`code/problem1/preprocess_media.py`；编辑列表候选映射：`code/problem1/map_transcripts.py`。输出：`/hy-tmp/E/problem1/media/`，逐样本`full.mp4`与`full-16k-mono.wav`、`manifest.csv`。本地留存的100条清单：同目录`manifest.csv`。重跑会核对源SHA-256并跳过已通过样本，失败条目可重试。

## 做了什么

1. 用`video_id + clip_id`逐条核对Excel与MP4，输入为100条且键一一对应；源视频计算SHA-256，不修改原文件/文本/标签。
2. 分别读取默认编辑列表视图与`ffprobe -ignore_editlist 1`的**完整底层音视频**轨道时长和起点。100条中90条的两种视图时长差异超过0.2秒；绝不能把默认解码选中的末段冒充原视频全程。
3. 用`ffmpeg -ignore_editlist 1`无损重封装完整音视频，另生成完整音轨的16 kHz单声道WAV。保留同一原片的两个派生文件，不把重封装结果当作需提交的原视频。
4. 对每条核对重封装前后的音视频轨道时长、实际解码帧数及帧PTS，核对WAV时长；清单记录状态、路径、时长、帧数和源哈希。

第一轮有10条（集中在`clip_id=0`）被帧PTS校验拦截：校验曾混用默认应用编辑列表与完整底层视图。修正为两边一致的全片PTS后只重跑失败条目，最终清单为**100/100条状态`ok`、100个唯一ID**；不能将首轮失败隐去。服务器派生视频约103,618,547字节，完整WAV约35,690,772字节，总目录约134 MiB；这些中间媒体**不应直接放入50MB提交附件**，提交的是题目要求的自生成时序特征、代码和复现说明。

## 编辑列表候选区间（已生成，不等于逐词对齐）

从原始MP4的`mvhd`、`mdhd`和逐轨`elst`读取movie/media时基及编辑区间，100条均生成了音频、视频各自的候选区间，保存在服务器`/hy-tmp/E/problem1/media/transcript-segments.json`，本地副本同目录。3条试验样本的末段音频与完整WAV做波形匹配：候选起点与实际匹配起点差约0.00002～0.00003秒，归一化相关性约0.994～0.996。这只验证**音频时间映射**；题面转写是否恰好覆盖候选片段、逐词边界是否准确，仍待人工回听，不把100条候选当作已完成的三模态对齐。
